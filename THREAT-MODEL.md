# Threat model

## Assets

- Downstream privileged credentials and irreversible actions.
- Tenant and actor identity.
- Policy decisions, Presence receipts, and Decision Dossiers.
- Intent integrity, grant uniqueness, and audit evidence.

## Adversaries and assumptions

The agent, its prompt, retrieved content, tool arguments, and model output are untrusted. The host running `IntentCapture`, `DecionisGate`, `SafeExecutor`, and registered handlers is trusted and must be isolated from the agent. Decionis and Presence service identities are independently authenticated.

Compromise of the trusted executor host or downstream provider is outside what this library alone can prevent. The design reduces that host's exposed interface and makes authorization evidence independently verifiable.

## Threats and controls

| Threat                                              | Control                                                                                                                                                               | Residual risk                                                                            |
| --------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------- |
| Prompt injection asks the agent to ignore policy    | Gate is outside the prompt and independently decides                                                                                                                  | A developer can still bypass the architecture                                            |
| Agent changes tool arguments after approval         | Exact canonical parameters and target bind to the intent hash                                                                                                         | Non-deterministic downstream interpretation must be avoided                              |
| Approval for action A is swapped onto action B      | Presence display and receipt bind the exact hash; Decionis re-verifies                                                                                                | Presence integration must preserve immutable fields                                      |
| Managed status for intent A is used with intent B   | Client checks escalation ID, intent ID, exact action hash, and expiry; grant claim rechecks the canonical intent                                                      | Trusted executor must retain the original captured intent                                |
| Invitation recipient is treated as an approver      | Invitation is an opaque locator only; Presence proves identity, role, and ceremony before signing evidence                                                            | Delivery-channel compromise may deny service but cannot create authority                 |
| Approval arrives after intent expiry                | Polling stops at the original intent deadline; late status or grant is discarded with recapture required                                                              | A fresh intent requires a fresh policy evaluation and ceremony                           |
| Old approval or grant is replayed                   | Short expiry, hash-bound idempotency key, `jti`, and atomic single-use consume                                                                                        | Provider records must remain available for reconciliation                                |
| Agent calls the provider directly                   | Provider credential and egress live behind the executor                                                                                                               | Network policy must actually prevent agent egress                                        |
| Agent chooses arbitrary code to run                 | Sealed action registry; no agent-supplied callback                                                                                                                    | Trusted registration code remains security-critical                                      |
| One proposer acts as, or on the intents of, another | Principals with their own credentials, roles and allowed actions; the principal's id inside the hashed intent; reconciliation and resumption only of one's own intent | The principals file and the platform's workload identity are the adopter's to keep right |
| Authority is unavailable or malformed               | Timeout, bounded response, strict validation, fail closed                                                                                                             | Reduced availability is accepted over unauthorized execution                             |
| JSON ambiguity or prototype pollution               | Strict schemas, forbidden keys, bounded canonical JSON, exact SHA-256 binding                                                                                         | Cross-language canonicalization requires conformance tests                               |
| Human approves misleading content                   | Action, target, and exact hash are mandatory display fields                                                                                                           | A human can still make a poor but authentic decision                                     |
| Shadow result is mistaken for authorization         | Observation has no grant, carries `OBSERVATIONAL` markers, and is rejected by the executor after casts and JSON round trips                                           | Consumer logs/UI must preserve the label                                                 |
| Shadow traffic obtains or delays real authority     | `SHADOW` wire mode issues no grant; pipeline refuses `ENFORCEMENT` authorities and runs on its own bound                                                              | A custom authority may still mint a grant; the pipeline discards and reports it          |
| Provider accepts an action but loses the response   | One-shot dispatch tracking returns unknown; read-only lookup uses the bound key                                                                                       | A provider without idempotency or durable lookup may remain permanently ambiguous        |
| Audit sink leaks or changes execution               | Redacted allowlist, bounded one-shot delivery, explicit failure policy                                                                                                | Best-effort delivery can leave evidence gaps; strict delivery can reduce availability    |

## Credential architecture

Unsafe:

```text
agent runtime: model key + Decionis key + provider admin token
```

Required:

```text
agent runtime -> proposal -> trusted executor: Decionis key + provider admin token
```

The agent runtime should have denied-by-default network egress. Open only the proposal channel to the executor. Give each handler the narrowest provider scope possible and use provider-side idempotency keys.

`deploy/kubernetes/` ships that shape as declarative infrastructure, in two namespaces with a
default deny in both, and `test/automation/DeployManifests.test.mjs` holds it to that shape in
`pnpm verify`. What each layer establishes, and what it cannot:

| Layer                        | What it establishes                                                                                                                          | What it does not                                                                       |
| ---------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------- |
| The agent zone's policy      | A caller has no `ipBlock` and no route off the cluster; its only path is the executor's listener on one port                                 | Anything, on a cluster whose CNI does not enforce NetworkPolicy                        |
| The executor's policy        | One way in from a labelled caller, and out only to DNS, the authority and the provider, each on 443                                          | The same caveat, and it names ranges rather than hosts unless Cilium replaces them     |
| The in-process egress policy | The same destinations again, resolved once per connection, socket pinned to the resolved address, verified against declared anchors and pins | Anything about traffic a handler does not originate                                    |
| Pod Security `restricted`    | A pod that is not non-root, not read-only, or privileged is not admitted at all                                                              | A kernel escape from a container that was admitted                                     |
| The posture check            | The process refuses to start outside the shape the manifest declares, naming the check                                                       | The isolation itself, which is the runtime's                                           |
| Projected workload tokens    | No shared secret exists between the zones; the cluster signs, the executor verifies against the JWKS                                         | Replay inside a token's ten-minute life, which idempotency and single-use grants cover |
| Operator RBAC                | On-call may read the deployment and take the halt flag, and has no verb on any Secret                                                        | What an operator may do through the executor, which the principals file scopes         |

Credentials reach the process as files and never as environment values: the executor verifies each
file is private to it, follows it when it rotates, and rebuilds the clients that hold a credential
rather than keeping a string. The provider credential exists only behind the executor, which is
what makes "the agent cannot call the provider" a statement about credentials as well as about
the network.

## Security invariants worth testing

- Changing any bound field, including the idempotency key carried in the trusted context, invalidates authorization.
- The wire binding contains exactly the contract's properties, and the idempotency header equals the intent ID.
- Exactly one of 100 concurrent consume attempts can execute.
- ALLOW without a grant cannot execute.
- Presence approval alone cannot execute.
- Production cannot instantiate fixture authority or verifier.
- Authority outage, timeout, oversized response, and invalid JSON all block.
- A provider exception before dispatch is distinct from an unknown exception after dispatch.
- Reconciliation cannot initiate a side effect and concurrent lookups share one in-flight request.
- Audit events contain no token, raw parameters, raw context, or provider result by default.
- A shadow observation cannot execute, cannot delay production, and never correlates to a grant.

## Accepted risks

These risks are accepted for the reference library rather than silently presented as mitigated. The Decionis maintainers own them and review the table before every stable release or when the trust boundary changes.

| Accepted risk                                                 | Rationale                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                        | Required compensating control                                                                                                                                                                                                       | Review trigger                                                               |
| ------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------- |
| A compromised trusted executor host can bypass the library    | Host compromise cannot be solved inside a process. `@decionis/agentsafe` verifies the posture it can observe (non-root, read-only root and working directory, no service-account token, no proxy, trust-anchor, key-log, option or inspector injection, secret files private to the process, Node's permission model denying writes, child processes and workers, the global fetch sealed), opens connections only to the origins its configuration names through anchors and pins it declares, listens over TLS with an optional client CA, and chains its evidence so that tampering after the fact is detectable; it refuses to run, or degrades, without that posture. `deploy/kubernetes/` declares the isolation around it and `pnpm verify` holds those manifests to their shape. The risk that remains is a working kernel escape from a container that passed every one of those checks | Apply the kit in its own order, keep Pod Security `restricted` enforcing, consider a sandboxed `runtimeClassName`, restrict provider credentials, monitor direct provider calls, and keep `EXECUTOR_POSTURE` enforced in production | Executor deployment, posture checks, or credential architecture changes      |
| The shipped NetworkPolicies are declarations, not enforcement | A manifest cannot verify that the cluster reads it. On a cluster with no NetworkPolicy-enforcing CNI, every policy in `deploy/kubernetes/` is accepted by the API server and ignored, and the agent zone silently has the network the node has                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                   | Confirm enforcement once, from a caller pod, by failing to connect to the provider's address rather than failing to authenticate to it; the runbook's "Proving the boundary" section says how                                       | The CNI changes, or the kit gains a rule anything depends on                 |
| The legacy caller mode makes every proposer one principal     | A configuration without a principals file has one caller, every registered action, and no operator; it exists so a first deployment and the offline proof need no file. Production refuses it unless `EXECUTOR_ALLOW_LEGACY_CALLER=true` says so by name, and the security stream says `LEGACY_PRINCIPAL_MODE` at start                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                          | Ship a principals file with a workload identity or a client certificate per caller before enforcement; treat the flag as a finding in review                                                                                        | A production deployment sets the flag, or a second caller appears            |
| The attempt journal's volume can be lost                      | The journal is per process and per volume: a pod that loses its claim loses the attempts it had open, which is the price of writing before dispatching rather than after                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                         | Give each replica its own claim, keep the volume as protected as the request traffic, and rely on the authority's lease recovery for what the journal cannot say                                                                    | Journal storage, replica count, or the authority's recovery contract changes |
| A halt is reachable from the agent zone                       | A flood of refused credentials or refused outbound requests halts the executor on purpose: stopping is the fail-closed answer to a caller that is behaving like a compromised one                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                | Set `EXECUTOR_HALT_ON_AUTH_FAILURES` and `EXECUTOR_HALT_ON_EGRESS_REFUSALS` to what the institution can tolerate, alert on `HALTED`, and keep an operator able to resume                                                            | Threshold changes, or a denial-of-service assessment of the agent zone       |
| Authority failure reduces availability                        | Failing open would permit unauthorized execution                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                 | Fail closed and require a fresh decision after recovery                                                                                                                                                                             | Availability target or timeout policy changes                                |
| A human can approve misleading but correctly bound content    | Cryptographic binding proves what was approved, not that the judgment was wise                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                   | Display the exact action, target, amount, and hash; apply policy limits before escalation                                                                                                                                           | Approval UX or Presence receipt schema changes                               |
| Cross-language canonicalization can drift                     | Multiple implementations may encode otherwise equivalent JSON differently                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                        | Keep the published conformance vector and require contract tests in every implementation                                                                                                                                            | Protocol or canonicalization changes                                         |
| In-memory replay protection is process-local                  | The implementation is a development primitive, not a distributed consume service; the host's own ceilings keep their windows in process memory for the same reason                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                               | Production uses the authority's atomic consume endpoint and provider idempotency                                                                                                                                                    | Any proposal to use `InMemoryReplayStore` in production                      |
| A post-dispatch provider outcome can remain unknown           | A response loss cannot safely be interpreted as either success or failure. The attempt is journaled before the provider is touched, so a lost outcome survives a restart and is reconciled read-only at start; what remains is a provider with no authoritative lookup                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                           | Use provider-native idempotency and read-only reconciliation; require a fresh grant for a new side effect                                                                                                                           | Handler or provider integration changes                                      |
| Best-effort audit delivery can leave evidence gaps            | Forcing every sink to be available can prevent otherwise safe execution, so `agent-safe.audit/1` delivery to an adopter's sink stays bounded and best-effort. Where `@decionis/agentsafe` is the host, its own evidence stream is hash-chained and checkpointed, so a line altered or removed after the fact is a hash mismatch or a sequence gap under `agentsafe verify-chain` rather than a silent absence. What remains is a sink that was unavailable while the process ran: still a gap, and one the chain marks rather than explains                                                                                                                                                                                                                                                                                                                                                      | Use bounded delivery, monitor sink health, choose strict pre-dispatch delivery where evidence is mandatory, and verify the chain rather than trusting a line count                                                                  | Audit retention or compliance requirements change                            |
